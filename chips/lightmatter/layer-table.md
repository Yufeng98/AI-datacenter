# Lightmatter Envise + Passage + Guide — Software Stack Layer Table

*as_of: 2026-08-08*
*device_class: Photonic Interconnect + Optics (compute product no longer marketed) — historically Photonic Compute + Interconnect*
*chip: lightmatter*

> **Scope note (2026-08-08).** Rows describing Envise, Idiom, PTC/DCI and ABFP16 are retained as architectural history: Envise is no longer listed in Lightmatter's product navigation, and no Idiom SDK change was found in the Apr–Aug 2026 window. Rows added in 2026 cover the Passage/Guide interconnect and optics line. Everything in the 2026 rows is vendor-stated and unshipped — Passage L20 samples from late 2026, Guide DR from Q4 2026.

| Layer | Component | Key Details | Open? | Notes |
|---|---|---|---|---|
| **Framework Integration** | PyTorch backend (Idiom) | `import lightmatter`; hooks into PyTorch computational graph via custom dispatch; no model code changes required for supported ops | Closed SDK | Equivalent role to `torch.cuda` for CUDA; hides photonic substrate |
| **Framework Integration** | TensorFlow backend (Idiom) | Same plug-and-play model via TensorFlow custom op registration; graph intercepted at runtime | Closed SDK | Less emphasized than PyTorch in recent docs |
| **Compiler / IR** | idCompile (Idiom Graph Compiler) | PyTorch/TF graph → Envise execution plan; partitions matmul subgraphs → PTCs; maps nonlinear ops → DCI CMOS electronics; ABFP16 quantization; phase-voltage encoding for MZI weights; multi-blade partitioning; analog noise compensation calibration tables | Closed | No user-visible IR; all transformations internal |
| **Compiler / IR** | ABFP16 Quantization Pass | Assigns shared exponents per block to match photonic analog dynamic range; minimizes quantization error relative to MZI noise floor; achieves near-FP32 accuracy (Nature 2025) | Closed | Lightmatter-specific analog precision format; no external standard |
| **Compiler / IR** | Multi-blade Partitioner | Automatically divides networks exceeding single-package capacity across multiple Envise blades (Passage interconnect); assigns layer segments to blades; schedules inter-blade data movement | Closed | Equivalent to automatic tensor parallelism; no user annotation needed |
| **Op Library** | Photonic Linear Ops (PTC) | GEMM / MVM via 128×128 MZI mesh; batched matrix-vector products; im2col conv as GEMM; fully-connected layers; Q/K/V/O projections in transformers | Closed HW | Executed entirely in photonic domain; not user-programmable |
| **Op Library** | Electronic Nonlinear Ops (DCI) | ReLU, GELU, Tanh, Sigmoid, Softmax, LayerNorm, residual add; executed on 12nm CMOS DCI chips co-packaged with PTCs | Closed HW | All nonlinear activations are electronic; photonics handles only linear algebra |
| **Kernel Library** | None (no user kernel API) | No user-programmable kernel language (no PTX, no Triton, no CSL equivalent); all ops are compiler-generated or hardware-fixed | — | Fundamental architectural constraint: photonic ops are not programmable at user level |
| **Runtime** | Idiom Runtime | Device allocation; Envise execution orchestration; DAC/ADC transfer scheduling; multi-blade synchronization; optical phase drift correction (periodic calibration); data transfer host↔DCI | Closed | Handles photonic-specific concerns (thermal drift, calibration) invisible in electronic runtimes |
| **Debugger** | idBug | Inspects digital activations at electronic-photonic interface boundaries; compares photonic vs. digital reference for precision debugging; identifies analog error accumulation per layer | Closed SDK | Essential for ABFP16 precision debugging; no equivalent in CUDA/cuDNN |
| **Profiler** | idProfiler | Per-layer latency breakdown: PTC optical compute time, DAC/ADC conversion time, data transfer time, phase-reload time; identifies pipeline bottlenecks between photonic and electronic domains | Closed SDK | DAC/ADC and weight-reload are the dominant latency sources, not compute |
| **Driver / Firmware** | Envise Device Driver | Kernel-mode driver for Envise PCIe device; manages phase voltage DAC programming; ADC readback; optical source control; calibration table management | Closed | Analogue of nvidia.ko but with photonic-specific calibration subsystem |
| **Communication** | Passage Interconnect (M1000) | 3D photonic interposer; 114 Tbps total bandwidth; 256 fiber connections; solid-state OCS (nanosecond reconfiguration); any-surface electro-optical I/O; connects thousands of XPUs in single domain | Proprietary HW | Replaces NVLink/NVSwitch role; also extends to datacenter scale via fiber. **2026-08-08: repositioned as Passage M1000 EVK — a rack-level reference/evaluation platform, not a shipping product tier** |
| **Communication** | Passage L200 CPO | 3D co-packaged optics; 32/64 Tbps per version; 112G PAM4; >200 Tbps total I/O per chip package; 5–10× over prior CPO; integrates with standard XPU/switch silicon | Proprietary HW | Targets existing GPU/XPU designs that want photonic I/O without full M1000 interposer |
| **Communication** | **Passage L20 (NPO / OBO)** *(new 2026-03-11)* | Unified optical engine for near-package optics and on-board optics; 6.4 Tbps per direction / 12.8 Tbps aggregate; 32 bidirectional optical ports at 200 Gbps/lane; 212.5 Gbps PAM4 SerDes; IEEE 802.3dj-compliant electrical signaling; 30 W max TDP; Corning CPO FlexConnect fiber coupling; A2 ASHRAE cold plate. Energy efficiency quoted as 3.0 pJ/bit (press release) vs 5 pJ/bit (product page); package as 2000-pin BGA (press release) vs 1827-ball BGA 37.5 × 26.4 mm (product page) — both genuine vendor inconsistencies | Proprietary HW | **Announced only; sampling begins late 2026.** BiDi multiplexing puts both directions on one fiber (vendor: ~50% fiber-count reduction). Vendor density claims: "4× pluggable density", "88% smaller by volume than OSFP". The "16 L20s replace 512 pluggables in a 102.4 Tbps switch" framing is **The Register's**, not the vendor's. Explicitly a bridge to a ~2028 CPO ramp (Harris) |
| **Communication** | **Guide 1 — VLSP Light Engine** *(new 2026-01-26/27)* | External light-source tier for CPO/NPO/OBO: hundreds of lasers and photonic components on one chip built in an HVM CMOS fab with on-PIC wavelength tunability; 100 mW+ optical power per fiber; 16 wavelengths at 100/200/400+ GHz spacing with a roadmap to 64; N+M redundancy by autonomously retuning a backup laser; replaces discrete ELSFP "laser farms" | Proprietary HW | New subsystem tier absent from the pre-2026 model of this stack. Guide 1 EVK is among the kits "sampling today". Design ecosystem: Cadence, Synopsys, GUC; PHIX separately |
| **Communication** | **Guide DR — liquid-cooled Laser NIC (LNIC)** *(new 2026-05-21)* | OCP NIC 3.0 form factor, in-chassis with zero front-panel footprint; up to 64 fibers; 200 mW optical power per fiber; supports 256 lanes at 200G; 51.2 Tbps aggregate per module; up to four modules in 1RU for 204.8 Tbps of CPO scale-up switching bandwidth; ~4× rack density vs conventional ELSFPs; ASHRAE A2; liquid cooled | Proprietary HW | **Announced only; sampling Q4 2026.** Vendor bills it as the industry's first liquid-cooled Laser NIC. All figures vendor marketing, independently unverified |
| **Management / Control Plane** | **CMIS module management** *(new 2026)* | Guide 1: CMIS-compliant telemetry, active stabilization and hyper-local thermal tuning maintaining sub-GHz wavelength precision. Guide DR: **CMIS 5.3** over **I2C / I3C**, plus **OCP MHS** (Modular Hardware System) integration | Industry standard interface, closed firmware | The first standards-based *software* surface in Lightmatter's stack: switch/host management software talks to Guide over stock CMIS rather than a Lightmatter-proprietary API. No public SDK, driver or API documentation has been released |
| **Packaging / Test** | **vClick dFAU** *(new 2026-03-11)* | Detachable fiber array unit with vertical / expanded-beam coupling engineered to survive advanced-packaging mold-and-grind flows; passive alignment; < 1.5 dB insertion loss across insertion *and* reinsertion; SENKO SEAT and Metallic PIC Coupler integration | Proprietary HW | Enables known-good optical engine verification at the **wafer level** before final assembly — a manufacturing-yield enabler for high-volume CPO. Vendor calls it "production-validated"; no GA date. "Detachable", not surface-attach |
| **Ecosystem / Standards** | **NVIDIA NVLink Fusion** *(new ~2026-06-03)* | Lightmatter to deliver Passage CPO and NPO products optically and electrically compatible with NVIDIA optical and SerDes technologies for semi-custom AI factories; claimed ~50% reduction in fiber and connector count | Third-party program | Announced in Lightmatter's own press release. It names neither Ayar Labs nor Marvell; the "alongside Ayar Labs and Marvell" grouping is IEEE Spectrum's (2026-07-09). Ayar Labs independently confirmed as a separate joiner (2026-06-02); **Marvell not independently confirmed** |
| **Communication** | Multi-blade Envise Fabric | 6.4 Tbps optical scale-out per Envise 4S server blade via Passage; idCompile schedules inter-blade activation transfers | Proprietary HW | Enables model parallelism across blades; managed by Idiom Runtime |
| **Assembler / ISA** | None | No user-visible ISA; no assembly language; no microcode; photonic matrix compute has no instruction fetch/decode cycle — weights are MZI phase states, inputs are optical amplitudes | — | Lowest user abstraction is PyTorch/TF graph; below that is entirely hardware-internal |
| **Compute Engine** | Photonic Tensor Core (PTC) | 128×128 MZI mesh implementing full SVD-decomposed matrix-vector product; 4 PTCs per package; one optical pass = one 128×128 MVM at ~1 ns traversal | Proprietary HW | 4 PTCs per package = 4 parallel MVMs per optical cycle |
| **Electronic Control** | Digital Control Interface (DCI) | 12nm CMOS; 2 per package; DAC: phase voltage programming (512 channels) + input optical modulator drive; ADC: photodetector readout → digital; nonlinear activations; LayerNorm; calibration | Proprietary HW | The electronic backbone of Envise; enables digital-accuracy control over analog photonic substrate |
| **Precision** | ABFP16 (Adaptive Block Floating-Point) | 16-bit with shared exponent per block; matches photonic analog dynamic range; achieves near-FP32 accuracy; replaces standard FP16/INT8 throughout the stack | Proprietary format | Demonstrated in Nature 2025: ResNet-50, BERT, Atari RL near-FP32 accuracy |
| **On-chip Memory** | MZI Weight State | Matrix weights encoded as electro-optic phase voltages in MZI electrodes; ~16K weights per 128×128 PTC; reloaded per layer by DCI DAC | Proprietary HW | Zero bandwidth required to access weights during compute (in-mesh); contrast with HBM weight streaming |
| **Off-chip Memory** | DDR4 + NVMe (per blade) | 1 TB DDR4 DRAM + 3 TB NVMe flash per Envise 4S blade; stores model weights (in float format, pre-phase-encoding) and host activations | Standard commodity | No HBM; photonic architecture does not require HBM-level bandwidth for weight access |
| **Host Interface** | PCIe + AMD EPYC | Envise package connects via PCIe to 2× AMD EPYC host CPUs per blade; host manages data loading, model orchestration, Idiom runtime | Standard commodity | Standard server PCIe interface; no custom host interconnect |
| **Scale-out Interconnect** | Passage M1000 / L200 / L20 + Guide | M1000: 114 Tbps, 4,000+ mm² photonic interposer, OCS, 256 fibers (announced 2025-03-31, now an EVK); L200: 32–64 Tbps CPO, >200 Tbps/package, 112G PAM4 (announced 2025-03-31); **L20: 12.8 Tbps aggregate NPO/OBO engine (announced 2026-03-11, sampling late 2026)**; **Guide 1 / Guide DR light-source tier (2026)** | Proprietary HW | Positioned as third-party interconnect for any XPU (never Envise-only); hyperscaler product. As of 2026-08-08 this **is** Lightmatter's product portfolio — the compute product is no longer marketed |
| **Benchmarks** | MLPerf | **Not applicable.** With no marketed compute product, Lightmatter has nothing that could be submitted to MLPerf. Prior accuracy evidence is the Nature 2025 Envise result (ResNet, BERT, Atari RL at near-FP32) | — | Recorded as not-applicable, not as an absence of results |
