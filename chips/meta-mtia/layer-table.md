# Meta MTIA — Layer Table

*as_of: 2026-08-08*

| Layer | Component | Detail |
|---|---|---|
| 1 — Hardware | PE Grid | v1/v2/2i: 8×8 = 64 PEs, each 2× RISC-V + MMA + DMA + nonlinear FFU. **MTIA 300: 12×6 = 72 PEs + 1 redundant 1×6 row (yield, boot-configured, SW-transparent) + 16 Message Engines; per PE 2× 64 B RISC-V vector cores + Dot Product Engine (2× 32×64B×32 MAC tiles, 7.82 TFLOPS/PE) + Reduction Engine + SIMD/SFU + Command Processor + Memory Layout Unit + Fabric Interface + Memory Bridge; RISC-V quad SMP control core (CPU-C)** |
| 2 — Compute | Peak throughput | v1: 102.4 TOPS INT8; v2: ~357 TOPS dense / ~714 sparse; 2i: 354 TOPS INT8, 177 TFLOPS FP16/BF16. **MTIA 300: 1,120 TFLOP/s FP8 GEMM, 560 TFLOP/s FP16/BF16 GEMM; SIMD 42.5 TOPS (engine) + 42.5 INT8/FP16 / 21.3 BF16/FP32 (RISC-V vector cores); INT8 GEMM removed, FP8 added; SIMD 32→128 elem/cycle; GEMM:SIMD 16:1 (was 32:1)** |
| 3 — Memory (on-chip) | Shared SRAM / LLC | v1: 128 MB; v2/2i: 256 MB @ 2.7 TB/s. **MTIA 300: 192 MB LLC (96 MB and 48 banks per side, 96 banks total) @ 11.4 TB/s R+W — lower capacity than 2i but 4.2× the bandwidth** |
| 4 — Memory (off-chip) | LPDDR5 (v1/v2/2i) / HBM3E (300+) | v1: 64 GB 176 GB/s; v2/2i: 128 GB 204.8 GB/s. **MTIA 300: 216 GB HBM3E, 6 twelve-high stacks (3 per side) @ 8.0 Gbps, 6.1 TB/s read *or* write; measured 5.57 TB/s (91% of peak) on BF16-add** |
| 5 — Interconnect (on-chip) | NoC | v2: 3.3× bandwidth over v1; low-latency PE coordination. **MTIA 300: mesh NoC with 6-PE cluster routers, L-routing (X then Y), virtual lanes for deadlock avoidance; no memory crossbar (removed vs 2i)** |
| 5a — Interconnect (in-package NIC) | Network chiplets | v1–2i: none. **MTIA 300: 2 network chiplets (25.6 × 9.3 mm each), 6 custom 800 Gbps (100 GB/s) RDMA/RoCE IP blocks each = 12 NICs / 1.2 TB/s; 8×112G SerDes per NIC die-to-die; express doorbells (WR is the doorbell, saves ~800 ns/transaction); 24,576 outstanding WRs across 1,024 QPs per IP block; 1,100 active QPs per NIC chiplet (QP caching removed)** |
| 5b — Collective offload | Message Engines | v1–2i: none. **MTIA 300: 16 MEs at PE-grid edges; each = 1 scalar RISC-V core (CPU-M) + 256 KB context RAM + shared Completion Queue + Near Memory Compute (128 B/cycle reduce or DMA, 96 B/cycle concurrent); up to 2.8 TB/s reduction throughput (>2× the 1.2 TB/s I/O BW) in one-third of the compute-engine area; accelerates Reduce / AllReduce / ReduceScatter** |
| 5c — Scale-up / scale-out | Rack fabric | v2/2i: not disclosed (rack-scale Ethernet). **MTIA 300: scale-up 16 accelerators = 1 rack @ 800 GB/s each (option to 1,000 GB/s); scale-out 200 GB/s per accelerator, 4,096-node L1 domain, 16K+ with L2; chassis = 16 compute blade slots + 6 network blade slots on paired cable backplanes; scale-up blade = low-latency ASIC, scale-out blade = disaggregated scheduled fabric (packet spray, in-order delivery, e2e credit); both liquid-cooled. MTIA 400: 72 devices per rack in one scale-up domain (switched backplane)** |
| 6 — ISA | RISC-V + FFU instructions | RISC-V cores generate instructions for MMA/DMA/nonlinear FFUs. **MTIA 300: RISC-V vector cores drive the Dot Product / Reduction / SIMD engines; CPU-M scalar cores run the Message Engines** |
| 7 — Runtime | MTIA Streaming Interface; **CUDA-like runtime API (300)** | Async dataflow scheduling, DMA management. **MTIA 300: CUDA-compatible runtime API supporting both eager and graph modes** |
| 8 — Driver | MTIA Firmware Driver | v1: 8× PCIe Gen4 (16 GB/s); v2/2i: 8× PCIe Gen5 (32 GB/s) — corrected 2026-08-08, ISCA 2025 and ISCA 2026 agree. **MTIA 300: 16× PCIe Gen5 (64 GB/s), 1:1 host:accelerator, 1 CPU with 512 GB RAM per accelerator.** 23 firmware releases fleet-wide in 2024 |
| 9 — Tensor API | MTIATensor | PyTorch device tensor type for MTIA |
| 9a — Collectives library | **HCCL (MTIA collective communications library)** | **New with MTIA 300: builds work packets and subgraphs of WQEs (SEND/RECV/WRITE/WAIT/SET/REDUCE) dispatched by CPU-C to the 16 Message Engines; drives NIC chiplets via RDMA verbs (rdma_core, ibv_create_qp); collectives traced by torch.export / torch.compile live in the same graph as compute; dynamic-shape collectives and device-resident AllToAll with dynamic send/recv counts are WIP** |
| 10 — Kernel compiler | Triton-MTIA + KernelEvolve | Triton → MLIR → MTIA native; KernelEvolve: multi-agent agentic kernel search/evolution (now published: ISCA 2026 Industry Track Session 4B, 2026-06-29). Kernels also written directly in C++. See also "Triton for MTIA" (IEEE Micro 2026) |
| 11 — Graph compiler | TorchInductor MTIA backend | Operator lowering, fusion, sparsity-aware codegen. **MTIA 300 adds ILP-based graph scheduling for peak-memory reduction and activation rematerialization; TorchInductor emits Triton codegen** |
| 12 — Graph capture | TorchDynamo / FX IR + **AOTAutograd** | Eager + compiled mode; torch.export for static shapes. **MTIA 300 training path: TorchDynamo forward-graph capture + AOTAutograd backward generation** |
| 13 — Framework | PyTorch | Eager mode + vLLM + torch.compile/export. **MTIA 300 adds FSDP2, DTensor, TorchRec, XFormers** |
| 14 — Workload | DLRM + LLM inference + Training (300+) | Recommendation/ranking primary; Llama inference; **MTIA 300 is the first training MTIA (ranking/recommendation training, ~150B-param DLRM with 99% of params in embeddings); LLM inference validated on DeepSeek-R1 / vLLM / InferenceMax** |
| 15 — Process / efficiency | TSMC 7nm (v1) / 5nm (v2/2i/200); **MTIA 300 node not disclosed** | 25 W v1 / 90 W v2 / 85 W 2i (65 W typ.); 44% TCO reduction vs GPU (ISCA 2025). **MTIA 300: 1.9 GHz, 0.85 V, 912 W (667 W typ.), liquid-cooled; 1.42× Perf/TCO vs a 500 W-power-capped H100 (780 TF/s, not the stock 1,000 TFLOPS at 700 W) on a production DLRM** |
| 16 — PE-local memory | PE SRAM | v1: 128 KB/PE; v2/2i: 384 KB/PE (~1.0 TB/s R+W). **MTIA 300: 512 KB/PE software-managed, split into circular buffers, 1.9 TB/s R+W** |
| 17 — Host interface | PCIe + decompression engine | v2: secure boot processor + on-chip weight decompression engine (new vs v1). **MTIA 300: 16× PCIe Gen5 (64 GB/s), one host CPU + 512 GB RAM per accelerator to avoid PCIe contention** |
| 18 — Packaging | Monolithic (v1–2i) / **2.5D CoWoS chiplet (300+)** | **MTIA 300: 1 compute chiplet 25.6 × 31.4 mm (~804 mm², reticle-sized) + 2 network chiplets 25.6 × 9.3 mm, on a 50.3 × 51.9 mm 3.2×-reticle interposer in a 77.5 × 77.5 mm package. Table I *Instances*: "7.2B gates, 511M FLOPS" — "FLOPS" is the paper's abbreviation for flip-flops, not throughput.** MTIA 400: 2 compute chiplets. MTIA 500: 2×2 smaller compute chiplets + HBM stacks + 2 network chiplets + SoC chiplet |
| 19 — Numerics | Supported data types | v1/v2/2i: INT8, FP16, BF16, structured sparsity. **MTIA 300: FP8 (S1E4M3 / S1E5M2), FP16, BF16, TF32, FP32 accumulate; INT8 retained only on RISC-V vector cores. MX4 and NVFP4 with row/block-wise scaling are NOT natively supported and fall back to RISC-V; native MX4 arrives in MTIA 400 (MX8/MX4)** |
| 20 — Roadmap (2026–2027) | MTIA 300/400/450/500 | Broadcom co-design (PR 2026-04-14, >1 GW commitment, no node or end-date stated); ~6-month cadence; HBM throughout; 300→500: 4.5× HBM BW, 25× FLOPs. **MTIA 400: +400% FP8 FLOPS and +51% HBM BW vs 300 (capacity not disclosed), 72-device rack scale-up, lab-tested only. MTIA 450: +75% MX4 FLOPS vs 400, 2× HBM BW, early 2027. MTIA 500: +50% HBM BW, up to +80% capacity, +43% MX4 FLOPS vs 450, 2027. No process node disclosed for any of them.** |
